# 登录、授权与快照接入契约

本文是下游系统将来接入独立后端时的设计与验收规范，不是本仓库已实现的功能清单。本仓库仍是纯前端、默认离线演示：没有登录、设备授权、后台任务、网络接口或真实业务数据，也不会自动同步任何外部系统。

## 1. 工作台权限与上游账号分开

工作台登录回答“谁在使用本系统”；设备及项目授权回答“这个身份和设备允许操作哪些功能”；上游账号登录回答“以哪个数据源账号读取或操作业务数据”。三者不能互相替代。

- 登录一个工作台后，其他同源工作台可以重新读取服务端会话，但必须分别核验本项目权限，不应强迫用户先进入另一个项目才能登录。
- 每个项目保留自己的登录入口、返回地址和退出说明。使用加密连接；返回地址仅允许当前部署的受信任页面，不能开放任意跳转。
- 一个上游登录成功，不能代表另一个上游也已登录。分别显示连接状态、稳定账号身份、会话范围与最近身份核验时间。
- 管理中心权限不自动授予业务读写，业务授权也不自动授予设备管理、他人授权或全局管理权限。
- 所有权限由服务端判断；隐藏按钮或前端记住的“已授权”文字不是授权证据。写入同时校验当前项目、账号范围、功能权限、有效期及请求防伪材料。

## 2. 授权、撤销与限时使用

授权记录至少区分授权对象、设备范围、项目范围、功能范围、起止时间、当前版本和撤销状态。读取、修改、导出及管理能力应分别设置。

项目级授权与撤销默认只影响选定项目。若动作会影响多个项目、共享会话或全部设备，确认页必须列出实际影响范围，不得把“撤销某项目访问”偷偷扩大为“清除全部上游登录”。退出当前项目、退出共享会话和退出全部设备也应有不同名称与行为。

“限时无需授权”应建模为服务端可撤销、有明确到期时间和功能范围的访客许可，而不是关闭鉴权。访客许可默认不开放管理能力、私有数据和业务写入；任何扩大范围都必须显式批准。到期与撤销在服务端立即约束新请求，不等待前端刷新，也不能依赖用户电脑的时间。短时页面缓存应及时清理或遮蔽，但无法收回用户已经合法下载的文件。

授权修改采用版本比较，防止两位管理者互相覆盖。操作后独立回读最终权限，记录最少必要的审计信息，不把访问凭据写入日志。

## 3. 统一与独立会话

统一会话允许获授权的项目复用同一个上游账号；独立会话仅服务指定项目。缓存键、请求上下文和写入预检都必须包含项目、上游系统、会话模式及稳定身份，不能只按页面地址缓存。

- 切换模式后重新读取所选范围的身份；不能为了让页面显示成功而静默回退到另一个账号。
- 初始化、页面重挂载、后台状态检查或另一个标签页的读取，仅观察已有状态，不得取消正在进行的登录验证。
- 只有用户明确取消、切换验证所属账号或模式、验证过期等适用事件，才结束对应验证；取消必须绑定原验证上下文，不能清除另一个标签页的新验证。
- 图片、滑块或其他人工验证遵守上游流程，由用户完成。验证票据只在服务端暂存、按用途绑定且只消费一次；不自动破解或绕过验证。
- 对同一次登录请求防重复提交；若提交结果不确定，先重新核验身份，不盲目反复提交密码。

不能把已知的常见密码硬编码进源码、批量尝试同名账号或在两个系统间自动猜测密码。可复用的是已经核验且仍被授权的会话；确需登录时，由用户明确提供该系统凭据。浏览器是否保存及同步密码由其密码管理器和用户设置决定，网页不能承诺密码必然只留在本机。

## 4. 暂态错误不等于退出

超时、断网、限流、服务端故障或响应格式错误，应显示“暂时无法重新核验”，保留最近可用的数据或会话记录，并进行有上限的退避重试。但保留记录不表示身份刚刚通过核验，也不能据此放行要求新鲜身份的写入。页面应分别显示已有会话和本次核验失败。

HTTP 成功不一定代表业务成功；接入层需按对应接口的明确契约解析业务错误。真正的身份失效响应，包括接口契约明确约定的业务未认证状态，才进入会话失效处理。

处理明确未认证响应时，采用比较并交换（CAS）：仅当失败请求使用的会话版本仍是当前版本，才使该会话失效。旧请求迟到返回的 401 不得删除用户刚刚登录成功的新会话。权限不足、项目许可到期与身份失效分别展示，不能一律提示重新登录。

## 5. 自动更新与快照锁

上游目录同步与公开快照发布是两个独立步骤：后者发布已有的数据，不会自行让上游目录变新。自动更新必须在已有授权范围内执行；它不是扩大权限或绕过上游验证的理由。

### 锁与部署权限

- 部署时预先创建同步锁，校验它是预期目录中的普通文件、不是符号链接，并设置实际同步进程所需的最小读写权限。
- 父目录保持只允许受控部署者修改，不通过放宽整个目录写权限来解决锁创建失败。
- 不删除、重建或替换仍可能被持有的锁文件；否则新旧进程可能锁住不同文件节点（inode），破坏互斥。部署变更也必须与同步任务协调。
- 区分“已有任务正在运行”与“锁不可用”。前者展示任务进度并等待回读；后者展示可诊断错误，不形成无休止的高频重试。
- 发布、升级与回滚后，使用真实运行身份验证锁可获取、第二个进程会被互斥阻挡、释放后可再次获取；不能只用管理员身份测试。

### 更新与展示

进入页面、恢复网络或页面重新可见时可触发轻量检查；隐藏页面降低频率。多个标签页共享同一范围的检查结果，在浏览器侧合并重复请求，服务端仍以锁和任务标识保证一次只执行一个同步任务，不能只依赖浏览器互斥。

失败时保留最近可用快照，并明确它的来源时间、授权范围和本次失败。切换身份、撤销权限后，不能继续展示原账号私有快照；公开快照与私有缓存分开处理。同步完成须独立回读任务结果、完整性信息和数据版本，再原子切换当前快照；收到“任务已受理”或进度提示不等于更新完成。

至少分别记录并展示：

- 源数据观测时间：实际从数据源成功读取的时间；
- 同步完成时间与任务标识：本次完整同步通过校验的时间及关联任务；
- 投影生成时间：公开或页面快照完成生成的时间；
- 身份核验时间：上游身份最近一次成功回读的时间。

身份核验、生成投影或读取旧缓存都不能改写源数据观测时间。价格、汇率、税费、包装和产品状态也应保持各自来源时间；没有取得新的数据时，不显示“已更新到最新”。

## 6. 下游接入验收清单

下列场景必须在隔离的测试环境验证。涉及真实业务写入时，需要另行获得明确授权，使用显式测试标识并禁止对外发送。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 直接访问任一工作台 | 可从本项目入口登录；回到本项目；项目权限独立核验 |
| 一个上游成功、另一个失败 | 状态分别显示，成功会话不被失败连带清除 |
| 撤销一个项目或限时许可到期 | 对应新请求被阻止；未受影响的项目仍可按其权限使用 |
| 页面刷新、重挂载或后台身份读取 | 不误取消正在进行的人工验证 |
| 旧验证或旧请求迟到 | 不覆盖新验证、账号选择或刚建立的新会话 |
| 断网、超时、限流或错误格式响应 | 保留适用范围内旧快照，显示核验失败；不伪称最新，不盲目重复登录 |
| 明确身份失效 | 仅使相同版本会话失效；明确提示重新登录原因 |
| 多标签页同时触发自动更新 | 浏览器合并重复检查，服务端仍只运行一个同范围同步任务 |
| 升级或回滚后以真实服务身份同步 | 锁权限正确、并发互斥有效，父目录未放宽，旧数据不会覆盖新版本 |
| 上游同步成功但公开发布尚未完成 | 两个阶段分别显示，公开页不提前宣称拿到新数据 |

完成测试、构建或阅读本文均不代表生产验收通过。本仓库自身仍只按离线演示的校验与发布流程交付。
