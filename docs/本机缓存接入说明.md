# 本机历史缓存接入说明

## 本次公开的内容

本仓库提供 `src/lib/local-read-cache.ts` 和 `scripts/local-read-cache.test.mjs`，分别是可复用的浏览器存储模块与合成数据测试。模块没有网络调用，也没有生产账号、实际缓存、服务端登录适配器或业务写入能力。

默认六条虚构产品演示没有导入此模块；安装或部署演示不会自动获得登录、真实数据同步或后台更新功能。以下为接入自己的授权应用时的实现要求。

## 先显示历史，再读取当前数据

1. 先独立确定当前是否有已验证账号。已有登录迹象但身份尚未确认时，禁止提前展示上一个账号的历史；显式调用 `setLocalCacheOwner(null, { allowHistory: false })`。模块也会识别约定的工作台身份 meta 标签，但其他应用不能仅依赖该约定。
2. 在允许个人浏览器离线展示时，读取 `getLocalCacheCatalog(route)` 的轻量目录，再按页面所需调用 `getLocalCachedRead(key)`；不要在首屏一次反序列化所有记录。
3. 历史卡片注明“本机历史 · 非当前数据”、原始数据时间和本机保存时间。历史展示与当前登录状态分别显示，不因有缓存就显示“已登录”。
4. 当前账号通过服务器身份回读后，设置已验证的数据分区，再发起正常只读业务请求。只对成功、符合业务结构且归属当前账号的响应调用 `captureLocalRead`。失败响应、登录页面、写操作结果和授权信息不缓存。
5. 当前数据成功返回后替换页面历史；失败时保留历史并提示未更新。不能修改原始观测时间，把本机保存时间冒充价格、税率或产品状态的核验时间。

缓存序列化与写盘延迟到空闲任务执行，不阻塞成功的业务请求返回；网络刷新与缓存展示需要由接入方分别实现。不要让严格业务请求在失败时悄悄返回历史并声称读取成功。

## 接口速查

| 接口 | 用途 |
| --- | --- |
| `setLocalCacheOwner(owner, options)` | 设置服务器已验证的数据分区，或设置未登录时是否允许历史展示 |
| `captureLocalRead(action, params, data, route)` | 非阻塞记录已成功且已授权的只读响应；无当前账号时不写入 |
| `getLocalCacheCatalog(route?)` | 只读记录目录，不加载业务正文 |
| `getLocalCachedRead(key)` | 读取当前可见账号分区中的一条正文 |
| `getLocalCachedReads(route?)` | 读取当前可见分区的全部或指定页面历史，较大目录请优先使用轻量接口 |
| `getLocalCacheInfo()` | 返回启用状态、当前可见记录数、大小、账号显示名及存储错误 |
| `setLocalCacheEnabled(false)` | 停止保存并隐藏历史，原有记录仍保留；重新启用可恢复展示 |
| `clearLocalReadCache()` | 清空此模块在当前站点保存的所有账号分区，不删除服务器数据或退出登录 |
| `LOCAL_READ_CACHE_EVENT` | 通知本机缓存视图重新检查；不能作为授权事件 |

开关和清空接口返回 Promise。界面必须等待成功，失败时显示错误，不能提前提示“已清空”。停用不等于删除；要删除记录请使用清空操作。

## 账号隔离与安全边界

`owner.id` 接受 `scope-` 加 64 位小写十六进制字符的分区标识；这只是格式校验，不是身份认证。接入方应由服务器在当前已验证账号、租户及数据权限范围下生成不暴露原始身份的不透明分区标识，不使用密码、会话材料或由用户任意输入的编号代替身份回读。显示名也应尽量少包含个人信息。

明确切换账号时，先隐藏旧历史、使旧请求失效，再设置新分区；新账号不得自动读取前一个账号。`setLocalCacheOwner(null)` 默认允许查看最后一个账号的本机历史，符合个人浏览器的离线需求；遇到明确禁止访问或共享设备模式时，使用 `{ allowHistory: false }`。未经登录不能新增历史或执行线上写操作。

模块会取消已经交给存储模块的旧代次任务，但它不管理调用方尚未完成的网络请求。接入方必须另外维护请求代次：

- 请求开始时记录当前账号、数据范围及代次；
- 切换/退出账号、停用、清空和权限变化时递增代次并尽可能中止旧请求；
- 响应回来时再次比较这些值，只允许完全一致的成功响应渲染当前视图或进入缓存；
- 同样处理其他标签页的设置或清空通知，避免旧请求晚到后重新写回已清空内容。

模块包含认证字段、权限字段、签名链接及危险文本过滤，`status` 仅保存业务统计投影。操作名称必须在源码的 `ALLOWED_ACTIONS` 中；该名称列表只用于选择可缓存的读取类型，不附带任何接口地址或权限。过滤是附加保护，不保证任意未知业务对象都已完全脱敏；接入方应先采用业务字段白名单，特别检查自由文本与自定义字段。

## 存储容量、隐私与恢复

- 使用当前站点的 IndexedDB，不把大数据放进同步网页存储。总计最多 80 MB、400 条记录，单条最多 30 MB；浏览器实际额度可能更低。
- 达到上限时，按最近访问顺序淘汰旧记录。替换和淘汰在同一事务内，写入额度不足时回滚，保留原来可用的记录。
- 同一账号、读取类型和规范化参数共用一份记录，可关联最多 12 个页面路径，减少重复正文。
- 缓存内容未加密，网页同源代码、浏览器使用者或本机管理者可能读取。只应在信任的个人设备使用；不应宣称“仅账号本人可解密”。
- 允许登出历史展示是显式产品选择，不适合公共电脑；清空本模块不等于清空浏览器其他缓存或其他应用的数据。
- 浏览器清理、无痕模式、额度不足或隐私策略可能导致无法持久化。存储失败不能阻断正常线上读取，界面应如实显示失败。
- 只保存已经成功读取并且满足限制的内容，不主动下载整库、图片、视频或附件，也不是完整离线应用。媒体 URL 的历史存在不保证媒体仍可访问。
- 历史价格、汇率、产品状态与税费不能解除正式报价、下单、授权、报关等当前核验要求；没有离线写入队列或自动补发能力。

## 测试与接入验收

运行 `pnpm test` 可执行全部测试，运行 `pnpm run ci` 同时执行开源边界、许可证、测试、类型和构建检查。缓存测试使用事务式 IndexedDB 模型，覆盖延迟捕获、字段过滤、账号隔离、路径复用、容量淘汰、原子回滚、停用、清空与重新加载，不读取浏览器真实资料、不连接任何业务接口。

这些单元测试不是真实设备验收。实际接入后仍需在目标浏览器验证：首屏历史展示速度、在线替换、断网、账号 A 切换 B、清空期间晚到响应、跨标签页停用、明确拒绝访问时隐藏历史、存储失败提示，以及历史不能放行线上写操作。
